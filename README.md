## Week 2: Python for Security and HTTP Fundamentals

### Overview

Week 2 focuses on Python programming for security scripting and understanding HTTP communication between web browsers and web applications.

A basic Python HTTP interaction script was developed using the Requests library to communicate with OWASP Juice Shop running in a local Docker environment.

### Objectives

- Understand HTTP methods, including GET and POST.
- Inspect HTTP status codes and response headers.
- Use Python Requests to communicate with a web application.
- Save HTTP interaction results in a structured JSON report.
- Learn how to analyse web application login requests and responses.

### Tools and Technologies

- Python 3
- Requests library
- OWASP Juice Shop
- Docker
- Google Chrome Developer Tools
- Burp Suite Community Edition (optional)

### Installation

1. Clone the repository:

   ```bash
   git clone https://github.com/Robert-ux-dev/Financial-Web-Security-Scanner.git
   ```

2. Navigate into the project directory:

   ```bash
   cd Financial-Web-Security-Scanner
   ```

3. Install the required Python dependencies:

   ```bash
   py -m pip install -r requirements.txt
   ```

4. Ensure Docker is running and OWASP Juice Shop is accessible at:

   ```text
   http://127.0.0.1:3000
   ```

### Running the HTTP Script

From the project root, execute:

```bash
py src/http_basics.py
```

The script sends an HTTP GET request to the local target and displays information about the response, including:

- HTTP status code
- Content-Type response header
- Server response header
- Response size in bytes
- A short preview of the response body

The script also saves the results to:

```text
reports/week2_http_report.json
```

The report includes the target URL, execution timestamp, request method, response headers and other available response details. If the request fails, the report records the error.

### HTTP Login Analysis

Browser Developer Tools are used to inspect login-related HTTP requests and responses generated by OWASP Juice Shop.

The analysis covers:

- Request URL and HTTP method
- Request headers and payload structure
- Response status code and response body
- Cookie and session behaviour
- HTTPS usage and relevant security headers

Detailed observations are documented in `Docs/week2_http_analysis.md`.

### Security and Testing Scope

Testing is restricted to the deliberately vulnerable application running in the local lab environment.

The Week 2 HTTP script performs a basic GET request. It does not submit login credentials, exploit vulnerabilities or perform a comprehensive security assessment.

Credentials, session tokens and other sensitive information should not be committed to the repository.
